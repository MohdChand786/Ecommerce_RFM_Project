# E-Commerce Customer Retention & RFM Segmentation

## 📌 Executive Summary
Customer retention is the lifeblood of e-commerce, yet many platforms suffer from a "leaky bucket" business model. This project analyzes a real-world e-commerce database of ~95,000 customers to identify churn risks and segment the user base for targeted marketing. 

By building an end-to-end automated ETL pipeline and conducting RFM (Recency, Frequency, Monetary) analysis, I uncovered a critical business vulnerability: **76% of total historical revenue ($12.1M) was generated by one-time buyers**, while the highly lucrative "Champion" segment contained only 8 individuals out of nearly 100,000 acquisitions.

## 🛠️ Tech Stack & Architecture
* **Database:** MySQL (Relational schema, Foreign Key constraints, aggregations)
* **ETL & Data Engineering:** Python (SQLAlchemy, PyMySQL) to bypass local memory limits and automate data ingestion/extraction.
* **Data Science / Analysis:** Pandas (Quantile scoring, custom segmentation logic, statistical distribution).
* **Visualization:** Power BI (DAX Calculated Columns, interactive slicers, KPI tracking).

## 🚀 Key Business Insights
1. **The Retention Crisis:** The median customer purchase frequency is exactly **1**. At least 50% of acquired customers make a single purchase and never return.
2. **The Revenue Treadmill:** 37,064 customers (~40%) have completely churned. The business relies heavily on constant, expensive new customer acquisition to maintain its $15.84M revenue.
3. **The VIP Opportunity:** Customers who reached the "Champion" status spent an average of **$933 each** (compared to the $107 median). Identifying and nurturing users into this tier could drastically reduce Customer Acquisition Cost (CAC) and boost LTV.

## 🏗️ Project Pipeline

### Step 1: Automated Data Ingestion (Python to MySQL)
Wrote automated Python scripts using `sqlalchemy` to connect to a local MySQL instance. Temporarily bypassed foreign key constraints to completely drop and reload parent/child tables (Orders, Customers, Order Items), successfully ingesting ~100,000 transactional rows.

### Step 2: SQL Aggregation & RFM Extraction
Built multi-table SQL joins bridging the gap between unique customer IDs and individual order items. Extracted the maximum purchase date per user (`MAX`), transformed string data into strictly formatted MySQL `DATETIME` formats using `STR_TO_DATE` and `LEFT`, and calculated days since last purchase (`DATEDIFF`).

### Step 3: Python RFM Scoring & Segmentation
Extracted the aggregated dataset back into Python using an automated SQL query wrapper. Utilized `pandas.qcut()` to distribute Recency and Monetary values into 1-to-5 statistical quantiles. Applied custom logic to handle the heavily skewed Frequency data, culminating in a 3-digit RFM score for every user.

### Step 4: Executive Dashboard (Power BI)
Imported the scored dataset into Power BI. Wrote DAX `SWITCH()` logic to translate numerical RFM scores into actionable marketing segments (e.g., "Recent & Promising", "Needs Attention", "Lost / Churned"). Built an interactive visualization layer allowing the CMO to instantly filter the $15.84M revenue by specific customer cohorts to generate targeted email lists.
